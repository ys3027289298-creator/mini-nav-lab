# hotupdate

分块地图热更新的原子性模型。崩溃堆栈的链路是：更新地图 → 释放块 →
`free` 发现堆已损坏；其下是加载块与导航帧交错。根因是**新块加载与旧块
释放交错在同一张活动表上**，导航查询拿到悬空指针（freed 槽）或拼出半新
半旧的图（部分槽已是新代、部分还是旧代）。

`make test` 跑离散帧模拟，所有违例带帧号与查询坐标，确定性可复现；
`make plot` 输出两条权衡曲线到 `artifacts/`。

## 1. 原子更新必须满足的表达式

设世界被切成块集合 $C$，第 $g$ 代地图是每个块到其代版本的映射
$M_g: C \to V_g$；查询 $q$ 在其生命期内访问的块集合为 $C_q$。

**查询级原子性（无半新半旧）**：任一查询触及的所有块必须同属一代，

$$
\forall q,\ \forall c_1,c_2 \in C_q:\quad G(q,c_1) = G(q,c_2)
$$

其中 $G(q,c)$ 是查询 $q$ 访问块 $c$ 时该槽实际所属的代。等价地，记查询
进入系统时的发布指针为 $P_t$（$t$ 为帧），要求

$$
\forall q \text{ 出生于帧 } t,\ \forall \tau \in [t,\,t+L_q):\quad
\operatorname{gen}(q,\tau) = P_t
$$

即查询一生持有一个代快照，发布指针的任何后续翻转对它不可见。

**全局视角的原子切换**：令 $P_t$ 为帧 $t$ 的活动代，

$$
\forall t:\quad P_t \in \{M_{\text{old}},\,M_{\text{new}}\},
\qquad P_t \neq \text{mixed}
$$

指针只能整体翻转，不存在"部分块已切、部分未切"的可见状态。

**存活性（无悬空）**：查询持有的代在其整个生命期内不得被回收，

$$
\forall q \text{ 持有代 } g,\ \forall \tau \in [t,\,t+L_q):\quad
\neg\operatorname{dead}_\tau(g)
$$

三条合起来才是完整规格：前两条消灭 torn（半新半旧），第三条消灭
dangling（悬空）。

## 2. 最小步骤数：三步，顺序不可换

满足上面三条的最小序列是经典的三阶段 RCU：

1. **L 加载**：在影子区把新代 $M_{\text{new}}$ 的全部块加载完，活动指针
   不动；
2. **S 切换**：一次指针发布 $P \leftarrow M_{\text{new}}$，旧代整体退休
   入队；
3. **R 延迟释放**：等宽限期过后，回收退休队列里的旧代。

三步不能合并、不能换序，理由各有一条反例（模拟在 `run_ordering` 中对
6 种排列逐一实测，T=4 窗口）：

| 排列 | S 在 L 前？ | torn 帧 | 结论 |
|---|---|---|---|
| **L S R** | 否 | 0 | 唯一同时守住两条轴的规范序 |
| L R S | 否 | 0 | torn 安全；R 与 S 的帧内先后由宽限队列兜底，真正的释放风险由 k 控制 |
| S L R | 是 | 2（首帧 1，坐标 (1,14)） | 指针先翻、影子未装满，查询读到未加载块 |
| S R L | 是 | 8（首帧 1，坐标 (5,0)） | 同上，窗口更长违例更多 |
| R L S | 否 | 0 | torn 安全，但 R 跑到 S 前时只能靠队列容量 k 拦住回收 |
| R S L | 是 | 3（首帧 2，坐标 (13,10)） | 双重违规：发布过早 + 回收过早 |

实测规律：**只要 S 排在 L 前面就必有 torn 帧**（表中三行全部 >0），
L 在 S 前的三行 torn 恒为 0。

为什么三步是下界：少掉 L，发布时新代不存在 → 悬空；少掉 S，两代没有
单一仲裁点，查询只能逐槽查表 → 半新半旧；少掉 R（立即释放），出生在
切换前、生命期跨过切换点的查询访问旧代 → 悬空。模拟中 k=0（等于取消
延迟释放）在三档分别产生 389 / 720 / 962 次悬空访问，验证了第三步
不可省。

## 3. 用切换期最大查询数反解保留代数

设更新周期为 $T$ 帧，查询最长生命期 $L_{\max}$ 帧（本模型
$L_{\max}=6$，每帧产生 $Q_{PF}=3$ 个查询）。

一次切换发生在帧 $s$。此时仍可能引用旧代的查询，出生帧落在
$[s-L_{\max}+1,\ s]$，共 $L_{\max}$ 个出生帧。每个旧代在被回收前，
最多要熬过 $\lceil L_{\max}/T \rceil$ 次后续切换。因此退休队列需要
保留的代数（含当前已退休、仍可能被引用的代）为

$$
\boxed{\,k^{*} = \left\lceil \dfrac{L_{\max}}{T} \right\rceil\,}
$$

从查询数方向反解同一结果：切换瞬间存活查询的容量上界是
$Q_{\max} \le Q_{PF}\cdot L_{\max}$（实测 14，上界 18）。这些查询按
出生帧分代，每 $T$ 帧的查询共享一个活动代，所以被引用的不同旧代数
就是 $\lceil L_{\max}/T \rceil$。两种推导给出同一个 $k^{*}$。

回收规则：队列长度超过 $k^{*}$ 时才弹出最旧的代。峰值内存随之确定——
任一时刻活动代 1 个、影子代 1 个、队列里至多 $k^{*}$ 个退休代：

$$
\text{peak}(k) = (k+2)\times N_{\text{chunk}}
$$

## 4. 两条曲线定代数（实测）

世界参数：4×4 = 16 个块，每块 16 格；96 帧；每帧 3 个导航查询，每个
查询生命 2–6 帧、访问 4 个格坐标。三档更新频率各跑一遍，先跑原地
释放的 naive 策略（崩溃现场），再对 RCU 扫 k=0..4。

**naive 原地更新（无原子性）——三档全部违规：**

| 档位 (T) | torn 访问 | dangling 访问 | 首个违例帧与坐标 |
|---|---|---|---|
| slow (8) | 252 | 137 | 帧 8，(2,0) |
| medium (4) | 438 | 282 | 帧 4，(11,12) |
| fast (2) | 413 | 549 | 帧 2，(4,7) |

**RCU 扫 k（dangling 数 / 峰值块数）：**

| 档位 | k=0 | k=1 | k=2 | k=3 | k=4 | 实测 k* | 公式 |
|---|---|---|---|---|---|---|---|
| slow T=8 | 389 / 32 | **0 / 48** | 0 / 64 | 0 / 80 | 0 / 96 | **1** | ⌈6/8⌉=1 |
| medium T=4 | 720 / 32 | 50 / 48 | **0 / 64** | 0 / 80 | 0 / 96 | **2** | ⌈6/4⌉=2 |
| fast T=2 | 962 / 32 | 423 / 48 | 102 / 64 | **0 / 80** | 0 / 96 | **3** | ⌈6/2⌉=3 |

RCU 策略下 torn 恒为 0（结构上不可能：查询只经一个发布指针取代，且
代只有满载后才发布）。悬空曲线在 k* 处归零，内存曲线随 k 线性上涨
（每代 16 块）——两条曲线的交点就是该档的最优点：

- `artifacts/dangling_vs_k.png` — 安全曲线，标注各档 k*；
- `artifacts/peakmem_vs_k.png` — 成本曲线，环标各档选定的 k*；
- `artifacts/sweep_table.csv` — 全部原始数据（图表的数据表视图）；
- `artifacts/run_report.txt` — 完整运行记录，含每条违例的帧号、查询
  id、坐标、持有的代与当前代。

**结论**：热更新期间的查询必须全部落在旧图或新图上。naive 策略在三档
都给出半新半旧/悬空的具体帧号与坐标；三阶段 RCU 在 k* = ⌈Lmax/T⌉
（slow=1、medium=2、fast=3）时三档全部归零，代价是峰值内存分别为
48 / 64 / 80 块（相对常驻 16 块的 3× / 4× / 5×）。频率越高，需要保留
的旧代越多，这就是延迟久则安全但内存涨、短则释放仍在用块的量化取舍。
