# sched — 寻路服务抢占式优先级调度 SLA 分析

跨团队 SLA：主线任务（P0）请求必须在**一帧内**返回，其余请求（P1 普通 / P2 后台）
可排队、可抢占。本目录用帧级离散事件模拟，从抢占判据推出并发上限，并用
「P0 一帧达成率」与「低优先级饿死率」两条曲线确定允许同时运行的低优先级请求数。

## 1. 判据与闭式表达式

设帧预算为每帧 `F` 个节点展开槽（`F=25`，由实测 P0 工作量的 p99 标定，1 帧 = 20ms）。
低优先级作业 `j` 的总工作量 `W_j`、已展开 `spent_j`、剩余 `remaining_j = W_j - spent_j`。

**抢占判据**（P0 到达时，对每个在役低优先级作业）：

```
preempt(j) = 𝟙[ ∃ P0 等待 ∧ remaining_j > F ]
```

剩余量 ≤ 一帧的作业让它本帧跑完——中断它只会作废工作、换不来 P0 的槽位。

**单次中断的作废损失**（已展开节点全部作废，整作业按原规模 W_j 重新排队重算）：

```
L_j = spent_j / W_j
```

**并发上限反解**（reserve 语义：每个在役低优先级作业最坏占 1 个槽；按 P0 工作量
的 99 分位 `W_0.99` 给帧定尺寸，保证 99% 的 P0 不抢占也能进帧）：

```
W_0.99 + k ≤ F
⇒ k* = ⌊F − W_0.99⌋ = ⌊25 − 20⌋ = 5
```

`k > 5` 时 99 分位的 P0 已无法与保留槽共存于一帧，只能靠抢占回收，而回收仅在
存在 `remaining > F` 的长作业时才成功，SLA 保证从这里开始降级。

## 2. 模型

| 组件 | 说明 |
|---|---|
| 帧步进 | 每帧 `F=25` 个展开槽，20ms/帧；5 秒红线 = 250 帧 |
| 工作量 | `calib/astar_calib.c` 复用 `grid/src/grid.c` 的四邻域 A*，采 9000 个算例统计每档请求的节点展开分布 |
| 帧内时序 | 低优先级先按公平份额 `⌊F/k⌋` 执行 → P0 到达并对长作业执行抢占、回收本帧槽位 → P0 用剩余+回收槽执行，放不下即违约 → 余槽回填 |
| 两种策略 | `preempt=True` 抢占式；`preempt=False` FCFS（低优先级先占帧，P0 吃剩余，SLA 失效） |
| 两种容量 | `reserve`（在役作业保留槽，体现并发互相拖累）；`ps`（纯处理器共享，对照） |
| 三档混合比 | main_heavy 35/45/20、balanced 20/50/30、bg_heavy 10/40/50（P0/P1/P2 到达占比） |

> 注：在「低优先级先按公平份额执行、P0 随后到达」的帧内时序下，每个在役作业
> 实际消耗的槽位恰好等于它保留的槽位，因此 `reserve` 与 `ps` 两策略的模拟结果
> 数值相同（见 `results/tradeoff_congestion_ps_balanced.csv`）。这互相印证了容量
> 记账的自洽：保留槽不是凭空的惩罚，而是对真实执行占用的核算。

两个实验工况：

- **calibrated（真实标定）**：真实 A* 展开分布、现实到达率。结论是低优先级作业到达
  稀疏，活跃并发到不了 k，抢占极少触发；P0 命中约 97% 且与 k 无关，瓶颈是帧预算 F
  本身（P0 最大 181 展开 > F），不是并发数。
- **congestion（受控拥塞）**：固定工作量 P0=10 / P1=100 / P2=600、util=7.0，让低优先级
  队列持续积压，从而两条曲线都能跨越 99% 达成线和 250 帧饿死线，呈现完整权衡拐点。

## 3. 主要结论（congestion / bg_heavy，5 种子均值）

| k | P0 一帧达成 | P2 饿死率 | P2 最长驻留(帧) | 中断次数 | 平均损失 L̄ |
|---|---|---|---|---|---|
| 1 | 93.64% | 3.85% | 408 | 624 | 0.386 |
| 2 | 96.82% | 28.25% | 1144 | 870 | 0.398 |
| 3 | 98.81% | 99.37% | 14127 | 3220 | 0.272 |
| **4** | **99.52%** | **99.37%** | 21779 | 3292 | 0.266 |
| 5 | 99.77% | 99.37% | 23212 | 3330 | 0.261 |
| 6 | 99.83% | 99.37% | 23849 | 4919 | 0.182 |

- **拐点 k=4**：P0 达成率首次越过 99%，但代价是 P2 类近乎全部饿死（驻留远超 5 秒）。
- **冲突时被牺牲的一类**：两项 SLA 无法同时满足——保 P0 的 99% 一帧达成，就必须牺牲
  P2 后台请求（bg_heavy 下 k≥3 后每轮 135 个 P2 到达中有约 134 个、99.4% 被饿死）；
  P1 普通请求在全部 k 下饿死数为 0。饿死数与到达数同口径（均只统计测量窗内到达的作业）。
- **抢占 vs FCFS**：同工况 k=4，抢占式 P0 达成 99.52%，FCFS 仅约 74% 且 P2 零饿死。
  抢占把主线 SLA 拉回达标，代价完全由最低档承担。
- 解析 `k*=5` 与模拟一致：模拟中 k≤5 普遍达标，k=6 时 99 分位 P0（20 展开）只剩 19 槽。

## 4. 复现

```
make calib     # 编译运行 A* 标定，生成 calib/calib.csv
make sweep     # 390 次调度模拟 -> sweep.json
make analyze   # 聚合 + 闭式反解 -> results/*.csv, *.json
make report    # 注入数据 -> report.html（浏览器打开，含悬停/表格/深浅色）
make test      # 调度器冒烟自检
```
