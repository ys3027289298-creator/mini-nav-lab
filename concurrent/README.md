# concurrent：并发改图的冲突合并

多人同帧修改同一张可走性地图时，服务端按确定性规则合并，各客户端重放同一规则，
保证合并后所有人的寻路结果与服务端权威结果一致。

## 冲突判据

设修改 `e_i`、`e_j` 的格子集合为 `S_i`、`S_j`：

```
conflict(e_i, e_j)  <=>  S_i ∩ S_j ≠ ∅
冲突范围 c_ij = |S_i ∩ S_j|        （交集大小即冲突波及格数）
```

代码中用恒等式 `|A∩B| = |A| + |B| − |A∪B|` 双向验证交集计算（`tierN_intersection_formula`）。

## 合并规则与重算代价

按 `(timestamp, player_id)` 逐格取最后写入者（LWW）：

```
owner(c) = argmax_{e ∋ c} (ts_e, player_e)
被覆盖修改 e_i 的丢失格子 L_i = { c ∈ S_i : owner(c) ≠ i }
```

被覆盖方必须重算路径，重算范围 = 冲突格子的可达影响区域，按块界定：

```
R_i = Reach(L_i) ⊆ L_i 所在块   =>   |R_i| ≤ B²
```

## 块尺寸的反解与取舍

约束「一次冲突的重算范围不超过单块、且不超过每帧重算预算 R_max」：

```
|R_i| ≤ B² ≤ R_max   =>   B ≤ ⌊√R_max⌋ = ⌊√16⌋ = 4
```

取舍两条曲线（W=16, H=12, WH=192）：

- 重算代价：`C_r(B) = B²`（块越大，一次冲突波及越多）
- 管理开销：`C_m(B) = WH/B²`（块越小，块数越多、元数据与维护越复杂）

总代价 `C(B) = α·B² + β·WH/B²`，取 α=β=1，极小点在：

```
B* = (β·WH/α)^(1/4) = 192^(1/4) ≈ 3.7  =>  B = 4
```

实测曲线（程序输出 `block_analysis`）：B=4 时 total=28 为最小，
与预算约束 B ≤ 4 一致。选定 **B=4**：每块 16 格，全图 12 块。

## 一致性验证（三档并发）

N ∈ {2, 4, 8} 名玩家同帧在走廊热点 (9,5) 附近加墙/拆墙：

1. 服务端：`server_merge` 逐格 argmax 得权威地图与每格归属；
2. 客户端：先乐观应用自己的修改（合并前分歧在此暴露，
   输出 `divergence: ... overwritten_by_edit=K cells=M`，即哪次修改被覆盖、影响几格）；
3. 再按 `(ts, player)` 顺序重放全部修改（`client_replay`），
   检查重放地图与服务端逐格一致、A* 路径与权威路径完全一致；
4. 每个被覆盖修改的影响区域必须落在单块内（≤16 格）。
