# bench — A* 开放表结构基准

同一份 A* 搜索逻辑，只换开放表数据结构，实测「寻路耗时—地图面积」曲线的拐点，
并据此为三档地图面积选型。所有结构产出**完全相同的搜索轨迹**（BFS oracle 校验），
因此耗时差异只来自数据结构操作本身。

## 三种开放表

| 变体 | 找最小 | 入表查重 | 缓存行为 |
|---|---|---|---|
| `array`  | 无序列表线性扫描 O(n) | 线性扫描 O(n) | 最友好，连续 int 数组 |
| `bitmap` | 无序列表线性扫描 O(n) | in-open 字节 O(1) | 友好，多一个字节标志 |
| `heap`   | 二叉堆 O(log n)，带 `pos[]` 索引 | O(1) | 父子节点跳跃，常数最大 |

## 两阶段复杂度与拐点

设一次搜索展开 `exp` 个节点、新入表 `ins` 个、开放表峰值容量 `omax`。

- **线性阶段（节点展开主导）**：每个节点展开的工作量为常数，
  `T_lin = ce · exp`，`exp = α·A`，故 `T_lin = ce·α·A = Θ(A)`。
- **平方阶段（开放表查找主导）**：数组开放表每次找最小/查重线性扫描，
  累计扫描量 `scan ≈ Σ n_open`。
  - 一般图论情形：开放表随已探索区空间填充，`n_open = Θ(A)`，
    `scan = Θ(A²)`，`T_quad = cs·Θ(A²)`。
  - **2D 嵌入式网格（本仓库实测）**：等 f 前沿是一条边界，受等周界约束
    `n_open = O(√A)`（实测 omax 标度指数 0.38–0.44），故
    `scan = Θ(A^1.5)`，高段渐近是 **A^1.5 而非 A²**。

**拐点 = 两条成本曲线的交点**：`ce·exp = cs·scan`。实测用每个查询自带的
`exp/scan` 计数器与标定常数直接定位，不依赖任何面积假设。

### 拐点位置与实现细节的关系

令每帧（每次展开）新入表节点数为 `k = ins/exp`，开放表容量 `c`。
开放表在 `c` 次入表后填满扫描主导区，故拐点处展开数

```
exp* = c / k
```

拐点面积（`exp* = α·A*`）：

```
A* = c / (k·α)
```

若开放表容量本身随面积线性增长 `c = γ·A`（空间填充前沿，γ = k²α/4 时对应
经典推导 `A* = 4c/(k²α)` 的形式），代入得容量—面积关系；但在 2D 网格上
`c = omax` 只按 √A 增长，该线性容量假设不成立，直接套公式会把 omax 高估
1.0–2.8 倍（见 `bench_knees.csv` 的 `formula_over_measured` 列）。
**拐点面积的可靠反解方式是成本交点，不是容量公式。**

## 两种地图族

| 族 | 生成 | 开放表几何 | omax 标度 | 高段斜率 |
|---|---|---|---|---|
| `scatter` | 12% 随机散障 | 波前（周长） | A^0.38 | ~1.6 |
| `maze` | DFS 回溯迷宫 + 6% 开环 | 走廊窄前沿 | A^0.44 | ~1.3–1.5 |

探针还测了空地图、BFS 树迷宫、递归分割、梳形齿图与 20–43% 密度散障：
**没有任何 2D 嵌入网格能让 omax 达到 O(A)**（最大 A^0.86，出现在 20% 密度）。
教科书式的硬线性→平方拐点属于 omax ∝ A 的抽象图，2D 网格上是 1 → 1.5 的软化拐点。

## 实测拐点（10 轮独立运行的中位数聚合）

成本模型 `T = ce·exp + cs·scan`，散障族 R² ≥ 0.999；迷宫族因工作集漂移
R² 0.62–0.80（真实几何效应，非标定失败，见文末）。

| 族 | 变体 | 拐点面积（格） | 拐点边长 | ce (ns/展开) | cs (ns/扫描项) |
|---|---|---|---|---|---|
| scatter | array  | ~700  | ~27 | ~36 | 0.41 |
| scatter | bitmap | ~2000–2300 | ~45–48 | ~39 | 0.49 |
| maze | array  | ~3100–3400 | ~56–59 | ~36 | 0.86 |
| maze | bitmap | ~3900–4000 | ~62–63 | ~36 | 1.40 |
| 两族 | heap | 扫描范围内无拐点 | — | log-log 斜率 1.21–1.31 |

逐次运行的精确数值见 `bench_knees.csv`。`bitmap` 用 O(1) 查重换掉 array 的
一半线性扫描，拐点面积右移约 3 倍；`heap` 在测到的 210 万格内始终展开主导，无拐点。

## 三档选型（约束：拐点必须高于目标面积，且小图耗时不劣化）

耗时为 10 轮独立运行、每轮 31 次重复的跨轮中位数。

| 档位 | 边长 | 面积 | array | bitmap | heap | 选定 | 实测耗时 | 拐点高于目标 | 相对 array |
|---|---|---|---|---|---|---|---|---|---|
| 小 | 17 | 289 | 3419 ns | **2929 ns** | 2945 ns | bitmap | 2929 ns | 是（~2000 > 289） | 1.17× |
| 中 | 65 | 4225 | 416 µs | 276 µs | **77 µs** | heap | 77 µs | 是（>210 万） | 5.39× |
| 大 | 257 | 66049 | 32.5 ms | 20.2 ms | **2.37 ms** | heap | 2.37 ms | 是（>210 万） | 13.75× |

- **小图是统计平局，已用 10 轮配对数据证实**：bitmap 2929 ns、heap 2945 ns，
  中位数比值 1.005；heap 仅在 10 轮中的 6 轮更快，两者跨轮区间几乎完全重叠，
  差异落在运行间噪声带（CV 2–3%）内。选型规则对小图档 5% 以内的平局显式偏向
  缓存友好的 bitmap——零回归风险（本聚合中它还是三者最快，0% 开销），且在更小
  的图上确定更快。`bench_tiers.csv` 的 `decision_note` 与 `overhead_vs_fastest_pct`
  如实记录该平局，不掩盖。
- 中、大图 heap 分别快 5.4×、13.8×，因为数组变体早已越过拐点进入超线性段，
  且都是三者中确定最快（0% 开销）。
- 选型由两条曲线共同决定：**耗时曲线**定常数（小图 heap 对数操作的大常数
  敌不过数组的缓存友好），**拐点位置曲线**定可行域（大图数组变体拐点不够高）。

## 复现

```
make verify     # BFS oracle：三变体最优性 + 轨迹一致性，两族地图
make run        # 单轮扫描 → bench_raw.csv
# 稳健聚合（推荐）：跑 10 轮再分析
make runs       # = 10 次 ./bench → bench_run_*.csv，再 python3 -P tools/analyze.py
```

输出：`bench_knees.csv`（拐点与标定）、`bench_tiers.csv`（三档选型）、
`fig_latency.png`（双族耗时曲线+拐点标注）、`fig_exponent.png`（局部标度指数）。
分析用 `python3 -P`：不把脚本目录注入 sys.path，避免同目录被植入同名模块。

## 实现过程中抓到的两个真实 bug（已修，oracle 回归）

1. `heap_siftdown` 下沉时与上一跳复制上来的陈旧副本比较而非保存的 `node`，
   破坏堆序，导致路径次优（L=64 给出 151，真值 127）并多展开大量节点。
2. 无约束最小二乘标定因 exp/scan 共线性返回负的单位成本；改用 heap 对照 +
   大开放表 T/scan 收敛值的物理标定。

## 迷宫族 R² 偏低的原因

迷宫 omax 非单调（走廊宽度随地图随机波动），且每次展开的实际成本随工作集
增长（T/exp 从 10 涨到 203 ns），单一全局常数对不准。散障族几何均匀，
同一模型 R² ≥ 0.997。报告保留两个 R² 而非只挑好看的族。
