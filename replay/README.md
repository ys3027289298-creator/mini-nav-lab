# replay

服务端寻路校验的**确定性回放**红队实验台。问题不是"怎么让寻路更快"，而是"作弊者如何利用不可复现性让服务端无法仲裁"。

## 确定性表达式

一次回放的输出唯一，当且仅当输入与迭代顺序同时固定：

```
path = F(map, start, goal, order)
replay_i == replay_j  ⇔  输入三元组相同  ∧  节点/邻域/合并的遍历顺序是输入的纯函数（与环境种子无关）
```

三类会破坏右侧第二项的实现，本台各给一个受控对照引擎（除被检验的变量外其余完全相同）：

| 模式 | 不确定性来源 | 判据（出现即不可复现） |
|---|---|---|
| `fixed` | 无：整数 g、(f, node id) 全序、固定邻域序 | 基线，差异帧必须恒为 0 |
| `hash` | open 集等 f 节点按 per-run hash salt 定序 | 同输入两次回放出现不同父节点 |
| `float` | float32 累加地形代价 + 严格 `ngf < gf` relax | 同节点两条整数等代价路由得到不同 gf（插桩计数） |
| `thread` | f 层并行扩展，候选集洗牌后 first-writer-wins 合并 | 无确定性 join，父节点随调度抖动变化 |
| `float_tie` | 浮点 relax **叠加** 盐序 tie-break | 舍入翻转真正传导进最终路径 |

## 关键结论（均由实验数据支持，非推断）

1. **严格浮点 relax 单独不足以破坏回放确定性。** 插桩显示每规模有 240–2680 次"整数等代价、浮点差 1 ULP"的父节点翻转，但 `float` 模式最终路径仍 100% 逐点相同——A* 的 `min` 语义对累加顺序不敏感，任何进入最终路径的节点都持有全局最小 gf。红队判据：**必须同时污染浮点比较和等 f tie-break（`float_tie`），舍入差异才传导到路径**，此时大地图达成率掉到 0%。
2. **无 join 的并行合并是最严重的缺口**：`thread` 在三档规模上 156/156 次比对全部分歧，大地图累计 20868 个差异帧。
3. **强制排序的开销随规模反转**：小图堆比线性扫描贵 +53%，大图反而快 −19%（O(log n) 对 O(n) 的 min 扫描），且两种实现输出交叉校验 0 处不符——确定性在大地图上是净收益而非成本。

## 构建与运行

```
make            # 编译
make run        # 跑实验并写 results.json（退出码 0 = fixed 引擎零差异帧）
make test       # 同 make run，接入统一自测
```

每档规模 4 个随机可走地图（BFS 保证起终点连通）× 40 次回放 = 156 次两两逐点比对，共三档：32×24 / 64×48 / 128×96。分歧时打印**第一处差异的点序号、两侧节点坐标、路径长度与成因**。

## 产物

- `results.json` — 全部模式的达成率、差异帧数、首次分歧证据、排序开销
- `chart.html` — 两条决策曲线（确定性达成率 / 排序开销），自包含可直接打开
- `curves_preview.png` — 同数据静态预览
- `tools/float_probe.py` — float32 累加顺序敏感性数值探针（stdlib，无第三方依赖）
- `tools/render_preview.py` — PNG 预览渲染脚本
