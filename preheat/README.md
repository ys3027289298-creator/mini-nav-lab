# preheat — 寻路缓存预热的收益/成本模型与批大小裁决

在玩家进入区域之前，把该区域的起终点路径离线算好缓存。本目录给出
**收益表达式 → 成本表达式 → 由空闲窗口反解批大小 → 双约束裁决** 的完整链路，
所有耗时常数都由 `src/bench.c` 在本机对 `grid/` 同款 A*（四邻域、曼哈顿
启发、线性开表，单次弹出 O(n)、最坏 O(n²)）实测校准，不使用虚构数字。

## 1. 符号

| 符号 | 含义 |
|---|---|
| `b` | 预热批大小：一个空闲窗口内预热的块数 |
| `M` | 该档地图的块总数 |
| `n_i` | 块 i 的可走格数；`Q_i = n_i(n_i-1)` 为有序起终点组合数 |
| `t_q(n)` | 未预热时的**首次冷寻路耗时**（实测拟合，ms） |
| `t_hit(n)` | 预热后的缓存命中查表耗时（实测，近似常数 ≈ 0.00003 ms） |
| `p_i` | 区域 i 的访问概率，`Σ p_i = 1`（本实验取均匀 `1/M`） |
| `W_idle` | 服务器空闲窗口长度（默认 30000 ms，可用 `--window` 改） |
| `SLO` | 首次到达等待硬约束 = **100 ms** |

## 2. 预热收益表达式

对块 i，预热把一次访问的等待从冷查询 `t_q` 换成查表 `t_hit`，期望收益为

```
R_i = (t_q(n_i) − t_hit(n_i)) · p_i            （每次访问期望省下的等待，ms）
```

整档地图的总期望收益（只对实际预热了的块求和）：

```
R = Σ_{i 预热} (t_q(n_i) − t_hit(n_i)) · p_i
```

实测 `t_hit / t_q` 在 1e-3 ~ 1e-5 量级（`make demo-run` 给出 170×–4000×
加速），所以 `t_hit` 相对 `t_q` 可忽略时，收益近似 `Σ t_q(n_i)·p_i`。

## 3. 预热成本表达式（随块数线性增长）

单块全量预热 = 块内每个有序起终点对各跑一次寻路：

```
c_i = Q_i · t_q(n_i) = n_i(n_i − 1) · t_q(n_i)
```

一个批次预热 b 块的总时长对块数线性：

```
C(b) = Σ_{i=1..b} c_i  =  b · c_ref   （同质块时，c_ref 为单块平均成本）
```

注意 `c_i` 对块大小 n 是 **n² × t_q(n)**，t_q 本身又随 n 呈 ~n^1.2 幂律，
所以单块成本约 n^3.2 增长——这是大块无法整块预热的根因。

### 成本模型的偏差方向（实测验证）

`make demo-run` 实测整表预热墙钟并与 `Q·t_q` 预测对照（单次运行的代表性
数值，重跑会有 ±50% 量级的计时波动，小块尤甚）：

| 块 n | 地形 | 实测预热 (ms) | 模型预测 (ms) | 模型/实测 |
|---:|:--|---:|---:|---:|
| 192 | open | 70.4 | 54.9 | 0.78 |
| 768 | open | 2626 | 2899 | 1.10 |
| 768 | choke | 6502 | 6571 | 1.01 |
| 1728 | open | 34643 | 55162 | 1.59 |

结论分两层，不能笼统说模型恒保守：

- **大块（n ≥ 768）模型稳定偏高（比值 1.01–1.6）**：全量预热里大量近距离
  短查询快于随机采样均值，规模化后缓存局部性稳定，按模型排产落在安全侧。
- **小块（n=192）单次预热仅几十毫秒，被调度器/时钟噪声主导**，比值在
  不同运行间于 0.8–3.3 跳动，模型既可能高估也可能低估。小块绝对成本只有
  ~0.1 s 量级，离 30 s 窗口有两个数量级余量，这点偏差不改变任何批大小裁决；
  若要对小块也保证不超窗，给模型乘一个安全系数（如 1.5）即可。

## 4. 由空闲窗口反解批大小

约束「预热总时间不得超过空闲窗口」：

```
C(b) ≤ W_idle   ⇒   b · c_ref ≤ W_idle
⇒   B_cap = floor(W_idle / c_ref)          （容量反解的批大小上界）
```

同质块时 `B_cap` 即批大小；异质块用脚本里的贪心装箱（成本降序 next-fit），
把能放下的块装进尽量少的窗口，单块成本 `c_i > W_idle` 的块直接判不可预热。

## 5. 两条曲线定批大小（取舍）

对 `b = 1..M` 扫描，画在同一张双轴图上（`output/curves_*.png`）：

- **蓝线 —— 首次到达等待**：`max_i 等待_i(b)`，预热到的块取 `t_hit`，
  其余取冷查询 `t_q` 的 p95；b 越大、命中越多、等待越低（单调下降）。
- **红线 —— 空闲窗口占用率**：`C(b)/W_idle ×100%`，随 b 线性上升。

可行批大小必须同时满足
`等待 ≤ 100 ms` **且** `占用 ≤ 100%`；取其中**最大的可行 b**（命中最高）。

窗口敏感性已验证反解公式（M 档，c_i≈8850 ms，`--window` 扫描）：
`W=10s→b=1、20s→2、30s→3、45s→5、60s→6`，与 `floor(W/c_ref)` 完全一致；
若窗口小到 `W < c_i`（如对 M 档给 5 s），则 `B_cap=0`、整档放弃。

## 6. 实测校准（`make measure` → `data/bench_*.csv`）

冷查询幂律 `t_q = a·n^k`（log-log 拟合，R² 见 `output/results.json`）：

| 画像 | mean 指数 k | p95 指数 k | 说明 |
|:--|---:|---:|:--|
| open | 1.19 | 1.17 | 12% 孤立障碍，高连通 |
| choke | 1.21 | 1.15 | 交错单口墙，蛇形路径、搜索面大 |

拟合在 **n=192..49152 实测范围内是插值**；超过 49152 的任何数字都标注为
外推。warm 查表实测与 n 无关（≈ 0.00003 ms），故不套幂律，取实测常数。

## 7. 三档结果（choke 地形，W_idle=30000 ms，SLO=100 ms）

三档控制总格数预算相近（~1.2 万格），只变块粒度，全部落在实测范围内：

| 档 | 块数 M | 块格数 n | 单块成本 c_i | B_cap | 选定 b* | 窗口占用 | 冷查询 p95 | 结论 |
|:--|---:|---:|---:|---:|---:|---:|---:|:--|
| **S** | 64 | 192 | 101 ms | 297 | **64** | 21.5% | 0.005 ms | 一个窗口全量预热，无放弃 |
| **M** | 16 | 768 | 8850 ms | 3 | **3** | 88.5% | 0.024 ms | 每窗 3 块，6 个窗口轮完，无放弃 |
| **L** | 7 | 1728 | 121134 ms | 0 | **0** | — | 0.062 ms | 单块就是窗口的 4.0 倍，**7 块全弃** |

三档在本机实测地形下冷查询 p95 都远低于 100 ms（SLO 余量 ≥ 99.9 ms），
**先咬合的始终是空闲窗口约束，不是延迟约束**。被弃块的玩家首次到达仍
走冷查询，但其等待本身满足 SLO，所以弃预热不违规、只损失收益。

### 放弃预热的块编号与原因

- **L 档：L-B00 … L-B06 全部放弃**
  原因 `preheat_cost_exceeds_window_cold_still_under_SLO`：
  单块全量预热 121 s > 30 s 空闲窗口（4.0 倍），`B_cap=0`；
  而冷查询 p95 仅 0.062 ms（max 0.095 ms），不预热也满足 100 ms SLO。
- **S / M 档：无放弃块。**

## 8. 压力档 X（外推，专门演示双约束真冲突）

n=1 048 576（1024×1024）的百万格块，冷延迟靠幂律**外推**得到
（`output/curves_X.png` 带 EXTRAPOLATED 标注）：

- 外推冷查询 p95 ≈ **116 ms > 100 ms SLO**（余量 −16 ms，外推值随校准
  运行在 100–120 ms 间波动，但稳定越线），单块预热成本 ≈ 1.15×10¹⁴ ms
  （约 3600 年），`B_cap=0`。
- 块 X-B00…X-B03 裁决为 `SLO_breach_and_window_conflict`：**预热塞不进
  窗口、不预热又击穿 SLO，两项硬约束同时失败**。
- 此情形没有调参能救，工程上必须改设计，而不是继续排预热：
  线性开表 A* 换二叉堆（开表 O(n)→O(log n)，直接削掉最坏 O(n²)）、
  分层/路标（contraction hierarchies、门户点）把单查压到毫秒级、
  或只预热高频起终点子集而非全 n² 对。上线前需在真实大块上实测，
  因为外推不反映 O(n²) 最坏形状，真实 max 只会更高。

## 9. 复现

```
make measure   # 写 data/bench_{open,choke,hit}.csv（冷/热延迟校准）
make demo-run  # 端到端：实测整表预热 vs 模型 Q*t_q，验证保守上界
python3 -I scripts/preheat_sim.py --tier all --window 30000
# 产物：output/results.json、sweep_*.csv、curves_*.png
# 单档：--tier S|M|L|X；改窗口：--window 60000
```

文件：`src/bench.c`（冷/热延迟基准）、`src/demo.c`（端到端模型验证）、
`scripts/preheat_sim.py`（幂律拟合、贪心装箱、批大小扫描、双约束裁决、绘图）。
